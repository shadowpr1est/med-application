# SmartMed — локальный MVP

SmartMed — адаптивное устанавливаемое веб-приложение на русском языке. Локальный режим работает без аккаунта; Firebase-адаптер активируется при настройке собственного проекта. Проект ещё не связан с живым Firebase/Netlify аккаунтом. Интерфейс собран Vite, доменные модели и календарная логика расписания написаны на TypeScript.

## Запуск

Требуется Node.js 20.19+ или 22.12+. В папке проекта:

```powershell
npm start
```

Откройте `http://localhost:4173`. Для телефона подключите компьютер и телефон к одной Wi-Fi сети и откройте на телефоне `http://<IP-адрес-компьютера>:4173`. Для установки используйте меню браузера «Установить приложение» / «Добавить на главный экран». Камера, уведомления и установка PWA требуют localhost или HTTPS.

Проверить production-сборку: `npm run build`. Проверить серверные функции: `npm run functions:build`. Локальный просмотр сборки: `npm run preview`. Остановить сервер: `Ctrl+C`.

## Что реализовано

- Локальный профиль и определение часового пояса устройства.
- Добавление, редактирование, пауза, возобновление и удаление лекарств.
- Несколько ежедневных времён приёма, дозировка, заметки, даты начала и окончания.
- Отдельные записи запланированных приёмов; изменение лекарства не переписывает историю.
- Выбор дней недели; при редактировании пересоздаются будущие неподтверждённые события.
- Статусы ожидания, скоро, напоминание, подтверждение, отсутствие подтверждения и пропуск по явному действию пользователя.
- Подтверждение конкретного приёма фотографией с камеры/файла или без фото (настраивается).
- История за день, неделю и месяц с фильтром по лекарству.
- Недельная статистика, которая описывает именно пользовательские отметки.
- Настраиваемые повторы напоминаний и срок до предложения связаться с доверенным лицом.
- PWA манифест, сервис-воркер и адаптация под мобильный экран.
- Firebase Email/Password: регистрация и вход включаются, когда заданы `VITE_FIREBASE_*`.
- При подключённом Firebase первая регистрация переносит локальные записи, вход загружает данные аккаунта, последующие изменения синхронизируются; фотографии копируются в приватное хранилище.
- Облачный профиль использует revision-подписку, чтобы отражать изменения с других устройств; время запланированного события сохраняется в UTC вместе с местными датой и временем.
- Push-токен браузера можно сохранить в закрытой коллекции устройств после входа и разрешения уведомлений.
- Cloud Functions планируют напоминания, повторы и email-эскалацию; перед отправкой функция заново проверяет статус события.
- Правила Firestore и Storage ограничивают доступ данными текущего пользователя.
- Netlify build/publish конфигурация для размещения статической PWA.

## Границы локального MVP

- В локальном режиме уведомления работают в браузере, пока приложение открыто. Фоновый Web Push и планирование требуют настроенного Firebase и развернутых Cloud Functions.
- При истечении срока приложение может показать локальное предупреждение и открыть подготовленное письмо или SMS. Отправить сообщение нужно самостоятельно. Автоматическая доставка доверенному лицу не реализована.
- Без параметров Firebase в `.env.local` или Netlify UI приложение остаётся локальным. Для облака создайте Firebase Web App, включите Email/Password и разверните Firestore/Storage rules.
- Фоновая доставка требует Cloud Functions/Cloud Tasks, Firebase Messaging VAPID key и регистрации устройства. Email доверенному контакту требует секрет `RESEND_API_KEY` и подтверждённый `RESEND_FROM`; SMS-провайдер ещё не подключён.
- Cloud Tasks разрешает планировать задачи не дальше 30 дней. Ежедневная функция добавляет задания, когда события входят в доступный период. [Ограничения Cloud Tasks](https://cloud.google.com/tasks/docs/quotas).
- В локальном режиме данные и фото остаются в браузере устройства. В облачном режиме данные и фото также сохраняются в Firebase. В настройках можно скачать JSON-копию локальных данных; фото, находящиеся только в Firebase Storage, в неё не входят. Серверная резервная копия пока отсутствует.
- Это PWA, не нативный Flutter-проект. Её можно установить из поддерживаемого браузера; сборка APK/IPA требует последующей упаковки в нативную оболочку и отдельной настройки разрешений/уведомлений.

## Технологии и структура

- `index.html` — страницы и навигация.
- `src/app.js` — UI-логика, история, статистика и локальные напоминания.
- `src/domain/types.ts` — типы профиля, лекарства, приёма и контакта.
- `src/domain/schedule.ts` — календарные события и обновление будущего расписания.
- `src/storage/localStore.ts` — локальное хранилище и миграция старой схемы.
- `src/styles.css` — адаптивные стили.
- `public/sw.js` — кэш статических файлов и открытие приложения по нажатию на уведомление.
- `public/manifest.webmanifest`, `public/icon.svg` — установка PWA.
- `netlify.toml` — production-сборка, SPA fallback и базовые заголовки безопасности.
- `firebase.json`, `firestore.rules`, `storage.rules` — эмуляторы и доступ к пользовательским данным.
- `functions/src/index.ts` — планирование событий, Cloud Tasks, push и email-эскалация.
- `functions/package.json` — зависимости и сборка Cloud Functions.
- `.env.example` — ключи конфигурации Firebase Web App (без секретов сервисного аккаунта).
- `vite.config.*`, `package.json` — разработка и production-сборка.

Локальная копия профиля, лекарств, ScheduledDose, контакта, настроек и фото сохраняется под ключом `smartmed.v1` в `localStorage`. При включённой Firebase согласованный email доверенному контакту может отправляться автоматически. Ни фото, ни отметка пользователя не доказывают, что препарат был проглочен.

## Следующий этап для полного технического задания

Серверный код использует Cloud Functions и Cloud Tasks. Для production создайте Firebase-проект, настройте Authentication/Firestore/Storage, Web Push VAPID и секрет Resend. Развёртывание Cloud Functions требует Firebase-проекта на тарифе Blaze; перед включением проверьте стоимость. [Cloud Functions for Firebase](https://firebase.google.com/docs/functions).

Порядок подготовки аккаунтов, секретов, Firebase и Netlify: [DEPLOYMENT.md](DEPLOYMENT.md).

## Проверка

Сценарий ручной проверки: добавьте тестовое лекарство с ближайшим временем, дождитесь напоминания при открытой вкладке, отметьте приём с фото/без фото, затем откройте «История» и «Статистика». В настройках можно выставить короткий интервал повтора и срок для контакта. Тестовое расписание не является медицинской рекомендацией.
